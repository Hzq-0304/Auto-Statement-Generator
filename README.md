# 自动对账工具

本地 Windows 桌面程序：导入报价单和送货单，匹配商品与价格，生成具有双来源追溯信息的 Excel 对账单。无需安装 Microsoft Excel，无网络服务。

## 功能

- 根据表头定位数据，支持多工作表、空白行列、合并单元格、文本数字和日期。
- 自动选用“圆养报价／单价二”，忽略参考报价；原始文件只读。
- 按真实商品编号或标准化名称、规格、单位匹配；模糊候选仅供人工确认。
- 预览报价与送货明细，支持人工选品、单位倍率、有效单价和确认原因。
- 先导出待核对稿；全部记录有明确价格且确认诊断后才能导出正式账单。
- J、K 列保留报价和送货商品序号，“来源明细”保留来源文件、工作表、原行及人工确认。
- 诊断详情、复制诊断、内置格式帮助；本地保存/恢复工作进度并校验来源文件是否变化。

## 直接使用

本机已打包版本位于 `dist/自动对账工具/自动对账工具.exe`。复制或发送整个“自动对账工具”文件夹，不能只复制 exe。发布版本也可从仓库的 Actions 构建产物下载。首次下载程序可能触发 Windows 未签名应用提示，本项目没有商业签名证书。

## 源码安装与启动

需要 Python 3.11 或更新版本（推荐 3.12），包含 Tkinter。Windows 官方 Python 安装包默认包含 Tkinter。

```powershell
py -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python main.py
```

也可双击 `启动工具.bat`，它优先使用本项目 `.venv`，否则使用系统 Python。普通使用者推荐直接运行已打包程序。

## 使用流程

1. 导入报价单，检查商品数与单价列。
2. 导入送货单，检查送货数、日期、单号和原金额异常。
3. 在送货预览勾选“只看待确认”，双击明细选择商品。规格、颜色、品牌或单位不同不能仅凭相似名称确认。
4. 单位换算填写倍率（如一箱20盒填20）；赠送可指定有效单价0。每次人工确认必须写原因。
5. 阅读诊断。可先生成待核对稿，空白金额未纳入小计；该稿不可作为最终结算。
6. 确认附加税率（默认0，已含税商品不重复加税），全部处理后勾选确认框，生成正式对账单。
7. 需要下次继续时点击“保存进度”。原文件发生变化后需要重新导入和复核。

## Excel 格式与样例结论

详见 [Excel 格式帮助](docs/excel-format-guide.md) 和 [样例结构分析](docs/sample-analysis.md)。

报价必需商品名称和实际单价列，送货必需商品名称和数量。序号、商品编号、规格、日期、单号、单位和备注按表头识别。样例报价没有原始序号，使用“工作表!行号”追溯。

三份样例不是同一版本的结算依据：报价主要在九月生效，八月历史账单还含额外记录、退货和人工调价。因此本工具按导入报价重新核算，不强行凑历史总额。样例验收详情见 [测试报告](docs/test-report.md)。

金额底层保留数量×单价的精确乘积，显示两位小数；合计按完整精度相加。Excel 公式可重算，首次打开前也有金额缓存。大写金额是导出快照，手改 Excel 后建议重新生成。

## 测试与命令行

```powershell
py -m unittest discover -s tests -v
py main.py --quote "报价单.xlsx" --delivery "送货单.xlsx" --output "待核对稿.xlsx"
```

正式命令行导出加 `--formal --acknowledge`，但有未匹配记录仍会拒绝导出。`--tax-rate 6` 表示未含税项目另加6%。GUI 推荐用于需要人工确认的业务文件。

## 打包

```powershell
py -m pip install -r requirements-build.txt
py -m PyInstaller --noconfirm --clean --windowed --onedir --name 自动对账工具 --add-data "assets;assets" --add-data "docs;docs" main.py
```

打包后的整个目录包含 Python 和依赖，目标电脑不需要自行安装。仓库提供 Windows GitHub Actions 测试/打包工作流，构建目录和业务数据不进入 Git。

`tools/build_template.mjs` 和 `tools/render_workbook.mjs` 仅供开发环境使用，依赖 Codex 的 `@oai/artifact-tool`。日常运行、测试和打包使用已提交的脱敏模板，不需要 Node.js 或此开发依赖。

## 常见问题

- **为什么匹配率不是100%？** 两份表的商品简称、规格、计价单位不一致。程序只自动确定可靠关系，其他项目需人工确认，避免错配价格。
- **没有报价序号怎么办？** 以原始工作表及行号作追溯编号，来源页还会保存完整报价名称和原始行。
- **旧版 `.xls`？** 请在 Excel/WPS 中另存为 `.xlsx`。`.xlsm` 可以读取，但宏不会执行或输出。
- **为什么不能生成正式账单？** 尚有待确认项目，或尚未勾选诊断确认框。
- **文件被占用？** 关闭已打开的输出文件后重试，或换一个文件名。
- **进度打不开？** 检查原文件是否被移动或修改。为避免旧确认应用到新商品，来源变化时会拒绝恢复。
- **需要更改历史价格或退货？** 在人工确认中指定有效单价并写原因；明确的退货以负数量记录输入，不依据含糊备注自动扣款。
- **数据上传了吗？** 应用本身不联网。公开仓库不包含本机原始表格、工作进度、诊断明细或生成账单。
