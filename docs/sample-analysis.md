# 三份样例的实际结构与实现依据

分析于 2026-10-05，先检查样例后确定实现。原目录只有三份 xlsx，无已有项目。

## 报价单

- 三个工作表：五金零配件、包装材料及其他、含税辅材。
- 第 1～4 行为公司、标题、客户和报价日期，第 5 行为主表头。
- 五金：A 品名、B 单位、C 参考报价、D 圆养报价、E 备注。
- 包装及辅材：A 品名、B 单位、C 单价一、D 单价二、E 备注。第 6 行补充 C 参考报价、D 圆养报价。
- 采用圆养报价／单价二，不使用参考报价或备注中的大批量供应价。
- 没有独立商品序号、货品编号和规格列。规格嵌入品名；来源编号采用“工作表名!行号”，同时保留完整品名。
- 五金有分类行（例如平垫、扳手），它们没有单位和数值价格。包装有带单位但未定价的商品，必须保留并提示缺价。
- 表格尾部说明主要报价自 2026-09-05 实施；含税辅材为 2026-08-28。前两表标注开专票加 6%，辅材为含税价，不能全表统一重复加税。
- 文件存在远至 XFB/XEO/XEN 的空白样式。解析实际存储的非空单元格，避免按最大行列建立巨大矩阵。

## 送货单

- 共 31 个工作表，首张“送货单模板”没有商品名称和数量，可跳过；其余 30 张合计 99 条有名称的明细。
- 第 1～5 行为抬头、标题、联系人、送货单号和日期。单号与日期可能在同一个合并单元格内。
- 第 6 行：A 序号、B 货品编号、C 品名及规格、D 单位、E 数量、F 单价、G 金额、H 备注。
- B 货品编号在样例中为空，A 序号是送货记录序号，不能当作跨文件商品主键。
- 不同工作表明细长度不同，结束于“合计”；存在空行、空金额与公式金额。
- 原单价与金额只作核验，生成金额由匹配报价重新计算。

## 对账单

- 三个历史月份工作表：202607、202608、202609。
- A1:I1 公司标题，A2:I2 月份标题，A3:D3 客户，G3 供应方；B5:I5 核对日期。
- 第 6 行：序号、日期、送货单号、品名及规格、单位、数量、单价、金额、备注。
- 明细从第 7 行开始，但实现通过表头识别输入，不将这个行号当输入约束。
- 尾部有合计、含税价、制表人、核对人、账户信息及审核签字。保留主要版式，导出时不沿用历史银行账号、联系人或旧合计。
- 增加 J 报价单商品序号、K 送货单商品序号。来源明细工作表记录文件、工作表、原始行、原始价格、匹配方式和人工确认原因。
- 每条金额保留精确十进制乘积（样例出现 1055.024），显示两位小数，合计对完整精度求和。未确认的金额留空，不能按零结算。

## 已确认的样例差异

1. 八月对账单有 102 条，送货簿只有 99 条。不能凭对账单补造送货记录。
2. 送货序号不连续，部分与对账单序号错位；必须保留送货原序号。
3. “20260829”工作表的单据正文为 2026-08-27，且单号与“20260827”重复。以正文识别并明确提示冲突，不悄悄改日期。
4. 黄色美纹纸：数量 220、送货单价 1.2、原金额 440，乘积应为 264。
5. 棉管35*45*2M 不开口：800 × 0.528 = 422.4，某送货记录写为 442.4。
6. 钢排钉报价按盒、送货按箱；历史对账备注 20盒/箱，但不能推定所有箱装商品都按 20 换算。
7. 赠送、退回、人工扣减存在于历史对账单，送货单未包含全部退货依据。不能自动重演历史结算。
8. 八月历史合计 H110=60536.354、调整后 I110=55871.55、含税 H111=59223，涉及人工调整和取整，不能作为本次自动计算的硬编码目标。

## 数据模型与匹配规则

- 商品：来源文件/表/行、来源序号、可选货品编号、完整名称、独立或提取的规格、单位、报价、生效日期、含税标记、备注。
- 送货：上述来源信息、日期、单号、数量、原单价/金额、备注。
- 匹配：真实货品编号（并校验名称/规格/单位）优先；其次标准化完整名称＋规格＋单位。序号不参与跨文件匹配。
- 标准化全半角、大小写、空白、乘号和尺寸中的无意义小数零；不去掉颜色、尺寸顺序、开口/不开口、等级或品牌。
- 模糊相似度只排序人工候选项，不自动确认。重复报价、缺价、单位差异、规格差异均保留待确认状态。
- 人工可指定报价商品、确认单位倍率和有效单价，必须填写原因；保留源值，不修改用户文件。
- 正式导出须所有记录有明确价格，并确认诊断提示；否则可导出含待确认标记的核对稿。

## 技术方案

Python + Tkinter 桌面界面，运行时仅依赖 openpyxl 处理 Excel，不依赖 Office、网络服务或浏览器。采用模块化解析、匹配、导出和界面。打包为 Windows 独立程序，适合普通用户双击使用。

仓库为公开仓库。提交程序、脱敏格式模板、文档和合成测试数据；原始业务表格、诊断明细及生成账单留在本地，不加入版本控制。
